# Using API evidence downstream

Keep method, path, source revision and uncertainty attached to the extracted facts when another artifact consumes them.

- **Documentation:** distinguish behavior defined in a specification, observed in a deployed build and inferred from route code. A route declaration does not prove response or authorization behavior.
- **Performance planning:** carry side effects, input data, authentication, idempotency, limits and correlation fields into the scenario. Missing traffic volumes remain an independent planning input.
- **Automation:** use confirmed contract fields for assertions. An uncertain response shape is not an acceptance criterion until resolved.
- **Knowledge-base updates:** incorporate the evidence at the caller's requested location, retaining provenance and contradictions. No particular knowledge-base tool or skill is required.

Describe a useful next step when requested. Name an installed workflow only when it is actually available. An extraction request does not authorize a test run, a new repository, an external message or publication.
